## Change and assistance summary

Removed the experiment scripts, their integration test, the CLI partition-size
property, experiment JVM option forwarding, and specialized fractional SELECT
timing. Restored one binding call followed by an exhaustive statement switch.
Historical experiment documents and safe error-log sanitization remain. Comments
in retained code were preserved; comments belonging to removed experiment code
were removed with that code.

Added DELETE to the grammar, AST, printer, binder, executor, and storage engine.
COPY now appends fresh partitions and advances the table version, including for
empty input. DELETE uses the same min/max pruning helper as SELECT, carries both
pruned partitions and candidates without actual matches, and writes survivors to
new PAX files. Fully deleted partitions have no empty replacement. A no-match
DELETE keeps its version, following the explicit decision in the design.

Catalogs are immutable versioned JSON files. Partition data and temporary catalog
contents are flushed before an atomic catalog rename publishes the commit.
Unsupported atomic moves fail without a non-atomic fallback. Statements acquire
a reference-counted snapshot before binding and use it throughout execution and
summary logging. Legacy flat catalogs remain readable by document identity;
ambiguous duplicate versions and mismatched filenames are rejected.

Retention keeps the current version and up to five versions for one hour, with
active readers overriding expiration. Cleanup deletes discovered catalog paths,
including legacy paths. Original partition files remain available. A future
orphan collector would compare files against all retained catalogs and active
writers; this change deliberately does not reclaim partition bytes.

Statements are serialized per StorageEngine. This keeps updates simple and safe
within one engine at the cost of concurrent statement throughput. Exercise 8's
optimistic writer-conflict handling and multiple live engines sharing one data
directory are outside this implementation. The durability claim covers process
crashes, not every filesystem's behavior under sudden power loss.

AI assistance covered code inspection, implementation planning, Java changes,
JUnit tests, independent review, and this entry. The contributor's design and
exercise description were read without modification. The independent review
reported no actionable correctness findings within this exercise's scope.
