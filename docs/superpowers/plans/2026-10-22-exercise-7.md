# Exercise 7 Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task by task. Track completed steps below.

**Goal:** Implement immutable copy-on-write DELETE, repeated COPY, and persistent versioned table catalogs.

**Architecture:** Each committed table version has one finalized JSON catalog. Writers create fresh partition files and atomically publish a complete catalog before updating the in-memory latest version. Statements lease an immutable catalog before binding and release it after execution.

**Tech Stack:** Java 25, Maven, ANTLR, Jackson, JUnit 6, existing PAX partition encoding.

**Spec:** `exercise-descriptions/Exercise7.md` and `docs/transactions-design.md`.

## Global constraints

- Git is read-only: no branches, commits, tags, or pushes.
- Preserve existing comments and the untracked CSV fixture.
- No speculative Exercise 8 transaction conflict detection or time-travel SQL.
- No-match DELETE leaves both partitions and catalog version unchanged (explicit user decision).
- Retention is one hour and at most five versions; active readers override both limits.
- Keep original partition files immutable and reuse shared predicate/pruning logic.

## Review focus

- Failed COPY or catalog publication must leave the last committed version readable.
- A statement must bind and scan the same version, even if another commit occurs.
- Partition names must never collide after deletion, failed writes, or restart.
- A candidate partition with no actual matches must be carried unchanged.
- Retention must protect readers and startup must ignore unfinished catalog files.
