# Exercise 7 implementation plan

> Execute in this session using superpowers:executing-plans and test-driven development.
> Git is read-only: no worktree, staging, commits, tags, pushes, or PR creation.

**Goal:** Remove the partition experiment runtime and implement Exercise 7 using
the contributor's transaction design.

**Architecture:** Preserve PAX files and the Volcano operators. Persist immutable,
per-table catalog versions and acquire reference-counted snapshots before binding.
COPY appends fresh files; DELETE reuses pruning and writes only changed partitions.

**Tech stack:** Java 25+, Maven 3.9+, ANTLR, Jackson, JUnit 6; no new dependencies.

**Spec:** `exercise-descriptions/Exercise7.md`, `docs/transactions-design.md`.

## Global constraints

- Keep user changes, including the untracked design and exercise, intact.
- Preserve existing comments in retained code; experiment-only comments belong to
  the experiment code being removed. Keep historical experiment documents.
- Use finalized `catalogs/versions/<table>-v<version>.json` and atomic rename;
  read legacy catalogs in place and reject ambiguous or malformed identities.
- Retain current and up to five versions for one hour; live leases override expiry.
- No-match DELETE keeps the version; empty COPY increments it.
- Partition files are immutable and never overwritten or garbage-collected here.
- No future transaction syntax or concurrent-writer conflict protocol (Exercise 8).
- Release v0.7, CI, merge, and human review remain manual under read-only Git.

## Review focus

1. A failed write or atomic publication must leave the old catalog readable.
2. A SELECT or DELETE keeps its snapshot across commits and retention.
3. Legacy table names resembling versioned filenames cannot alias another table.
4. Candidate partitions with no matching rows retain their original identities.
5. Restart ignores temporary catalogs and chooses numeric, not lexical, versions.
